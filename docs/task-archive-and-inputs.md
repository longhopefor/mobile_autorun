# 任务归档与输入查看

## 使用方式

1. 在「任务工作台」选择任务，点「查看任务输入」：查看完整目标、标题、正文、账号、业务要求、创建时模型配置、目标应用提示、计划时间及迭代上限。附件按原选择顺序展示，可预览图片和下载文件；「查看完整输入 JSON」提供全部保存字段。
2. 对已停止任务点「归档任务」，它从普通任务列表移到「归档任务」，输入、附件、截图、回放与执行记录继续保留。
3. 点列表上方「归档任务」，选择任务可查看输入和历史回放，也可「恢复到任务列表」。恢复只改变列表可见性，不恢复执行；暂停任务要单独点「继续执行」才重新入队。

排队、等待设备、等待模型、运行中及取消中的任务不能直接归档。先接管或取消，等待执行退出后归档；后端也拒绝仍有执行循环正在退出的任务。允许归档的状态是 waiting_human、reconciling、succeeded、failed、cancelled。

归档详情只读显示截图和回放，隐藏手机控制、继续和核验操作。输入查看在运行中和归档后均可使用，不发起模型调用或手机动作。页面使用创建时保存的模型快照；历史任务若没有快照，则完整 JSON 仍保留原配置 ID。

## 实现

- 迁移 `005_task_archive.sql` 增加独立 `archived_at` 字段及按用户、归档状态、创建时间的索引，归档不复用执行状态，也不删除任务。
- `GET /api/v1/tasks?archived=false|true&before=TASK_ID` 查询普通或归档任务，每页 100 条，按创建时间和 ID 稳定排序。前端完整遍历，最多 20,000 条；任务详情事件分页和回放沿用原有逻辑。
- `POST /api/v1/tasks/:id/archive`、`POST /api/v1/tasks/:id/restore` 在任务行锁下更新归档时间，与事件记录同事务；重复请求幂等。访问按任务 owner 隔离。
- `GET /api/v1/tasks/:id/inputs` 返回已保存 spec 和任务附件元数据，按不可变附件 ID 查询，不受素材库最新 100 条限制；文件路径和实际密钥不会进入响应。附件内容仍使用原有受 owner 限制的下载接口。
- 已归档任务拒绝直接继续；恢复后仍保持原执行状态和预算。执行入口也拒绝已归档任务，继续入队的条件更新与归档互斥。
